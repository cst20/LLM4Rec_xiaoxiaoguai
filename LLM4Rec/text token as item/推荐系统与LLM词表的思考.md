# 推荐系统与LLM词表的思考

## 一、背景与核心问题
Motivation1:Tiger所提出的SID一个优势在于能够以几千个token来表示千万级的物品数，让LLM当中text+物品交错出现成为可能，但是以往像SID方式来扩充词表，align需要很多高质量数据才能准确的让LLM理解SID，因此这两篇文章都不从SID的方式来适配物品库。
Motivation2：随着大语言模型（LLM）在各类垂直领域（如电商、推荐系统）的广泛应用，研究者发现：**模型本身的性能往往不是唯一的瓶颈，输入/输出的表示方式同样至关重要**。两篇论文其实都是从“领域推理效率”出发，通用 tokenizer 将领域专有词汇（如品牌名、SKU）切分成多个子词，导致 token 序列变长，推理变慢
《Vocabulary Customization for Efficient Domain-Specific LLM Deployment》
《Unleashing the Native Recommendation Potential: LLM-Based Generative Recommendation via Structured Term Identifiers (GRLM)》
## 二、提出的解决方案对比

| 方案维度 | 词汇定制方法（第一篇） | GRLM（第二篇） |
|----------|------------------------|----------------|
| **核心思路** | 扩展 LLM 原有的 tokenizer，加入高频领域词汇 | 不扩展词表，而是为每个物品生成一组**结构化的自然语言关键词**（Term IDs） |
| **表示形式** | 新子词（可能不是完整单词） | 完整、规范化的单词序列（如 `["doll", "educational", "wooden", "toddler", "interactive"]`） |
| **是否修改词表** | ✅ 是，添加新 token | ❌ 否，完全使用 LLM 原生词表 |
| **如何保证兼容性** | 将新 merge 操作**追加**到原有 merge 列表末尾，确保任何输入切分后的 token 数**不会比原来多** | 采用**弹性标识符映射**：先尝试直接匹配，若失败则通过结构相似性回退，确保总能映射到有效物品 |
| **如何让模型学会使用新表示** | 对扩展后的模型进行**继续全参数训练**（使用领域数据） | 通过**集成指令微调**，同时优化“物品→Term ID”识别和个性化推荐两个任务 |
| **关键评估指标** | token 数量减少比例、推理吞吐量（RPS）、新 token 的使用率 | 推荐准确率（Recall/NDCG）、标识符有效率（幻觉率）、跨域表现 |

## 三、共同的方法论特征

尽管两篇论文的应用场景不同，但它们在方法论上呈现出高度一致的三个设计原则：

### 1. **不破坏原有能力（向后兼容）**
- 词汇定制：新 tokenizer 永远不会比原 tokenizer 切分得更差（token 数量 ≤ 原切分）。
- GRLM：弹性映射机制保证生成的标识符总能落地到真实物品，不会输出无效内容。

### 2. **结构化、数据驱动的扩展**
- 词汇定制：基于领域语料训练新 tokenizer，再合并到原 tokenizer。
- GRLM：利用 LLM 自身和邻居物品信息，生成**一致且有区分度**的关键词序列。

### 3. **需要继续训练以“内化”新表示**
- 两篇论文都强调：仅添加新 token 或生成新标识符是不够的，必须让模型**通过训练真正学会使用它们**。  
  - 第一篇：继续训练后，模型在 >15 个词的序列中 **98% 的情况会使用新 token**。  
  - 第二篇：微调后，生成的 Term ID **有效率和直接命中率均超过 99%**，几乎不产生幻觉。


## 四、对 LLM 应用设计的共同启示

> **“表示层不是固定组件，而应与模型参数一起按需适配。”**

- 如果你希望 **提升推理效率** → 可以像第一篇一样，**有控制地扩展 tokenizer**，并保证不退化。
- 如果你希望 **提升生成式推荐的质量与泛化能力** → 可以像 GRLM 一样，**利用 LLM 自身词表构建结构化标识符**，避免词表扩展带来的成本。

两种方法**互不冲突**，甚至可以在一个系统中叠加使用：先用词汇定制提升领域输入效率，再用结构化标识符提升推荐语义准确性。



| 对比维度 | 词汇定制 | GRLM |
|----------|----------|------|
| 核心目标 | 推理效率 | 推荐质量 + 跨域泛化 |
| 表示来源 | 领域语料 | LLM 生成 |
| 是否扩展词表 | 是 | 否 |
| 关键创新 | 追加 merge 保证不退化 | 上下文感知生成 + 弹性映射 |
| 共同思想 | **让 LLM 的输入/输出表示与目标任务的分布对齐** | 相同 |
